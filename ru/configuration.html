Настройки¶

IduEdu хранит настройки времени выполнения в одном глобальном объекте iduedu.config. Функции загрузки и построения графов читают его при каждом вызове, поэтому изменение действует на всё, что выполняется после него в том же процессе. Большинство настроек можно также задать переменными окружения, которые читаются один раз при импорте iduedu.

from iduedu import config

config.to_dict()  # a snapshot of every current setting

Сервер Overpass и запросы¶

from iduedu import config

config.set_overpass_url("https://overpass-api.de/api/interpreter")
config.set_timeout(120)
config.set_rate_limit(min_interval=2.0, max_retries=5, backoff_base=2.0)

  • set_overpass_url принимает любой интерпретатор Overpass по http:// или https://, например собственный сервер или зеркало.

  • set_timeout задаёт тайм-аут запроса в секундах. То же значение передаётся Overpass как [timeout:...] в каждом запросе.

  • set_rate_limit разносит запросы не менее чем на min_interval секунд. Перед каждой попыткой IduEdu спрашивает у сервера свободный слот через /status и ждёт его. При сетевых ошибках и ответах HTTP 429, 502, 503 и 504 запрос повторяется до max_retries раз с экспоненциально растущей задержкой на основе backoff_base; при ответе 429 учитывается заголовок сервера Retry-After.

  • config.user_agent отправляется с каждым запросом. Укажите в нём то, что идентифицирует ваш проект: config.user_agent = "my-project/1.0 (me@example.org)".

  • config.proxies (словарь в стиле requests, например {"https": "http://proxy:3128"}) и config.verify_ssl передаются в каждый запрос.

Публичным сервером Overpass пользуется множество людей. Оставляйте темп запросов по умолчанию, если у вас нет собственного сервера.

Кеш Overpass¶

IduEdu кеширует исходные JSON-ответы Overpass на диске: границы, запросы уличных сетей, отношения-маршруты и их участников. Кеш включён по умолчанию и находится в .iduedu_cache относительно текущей рабочей папки.

from iduedu import config

config.set_overpass_cache(enabled=False)  # ignore the cache completely
config.set_overpass_cache(cache_dir="/tmp/overpass_cache", enabled=True)

Кеш хранит только ответы, а не обработанные графы. Очистите папку или отключите кеш, чтобы заново загрузить данные, например после правки нужных вам данных OSM.

Исторические снимки¶

Overpass может ответить на запрос по состоянию OpenStreetMap на заданный момент:

from iduedu import config

config.set_overpass_date(date="2020-01-01")                # 2020-01-01T00:00:00Z
config.set_overpass_date(date="2020-01-01T12:34:56Z")
config.set_overpass_date(year=2020, month=5)               # 2020-05-01T00:00:00Z
config.set_overpass_date()                                 # back to current data

Пока дата задана, маршруты метро запрашиваются как обычные отношения-маршруты: зоны остановок, станции и входы пропускаются, потому что Overpass ненадёжно выполняет такие запросы на произвольный момент времени, и в журнал пишется предупреждение.

Локальные файлы OSM вместо Overpass¶

Любая функция построения графов по OSM может читать данные из локального файла OpenStreetMap вместо Overpass API: те же уличные сети, маршруты общественного транспорта, зоны остановок метро и границы, отобранные теми же фильтрами и по тем же правилам выборки poly:, поэтому графы получаются такими же. Для этого нужна необязательная зависимость pyosmium:

pip install "iduedu[pbf]"

from iduedu import config, get_public_transport_graph, get_walk_graph, use_pbf

config.set_osm_source("pbf", path="city.osm.pbf")   # every following call reads the file
walk = get_walk_graph(territory=city_polygon)
config.set_osm_source("overpass")                   # back to the default

with use_pbf("city.osm.pbf"):                       # or only inside a block (same as config.use_pbf)
    pt = get_public_transport_graph(territory=city_polygon, transport_types=["bus", "tram", "subway"])

Переменные окружения IDUEDU_OSM_SOURCE=pbf и IDUEDU_PBF_PATH=/data/city.osm.pbf делают то же самое при импорте. В режиме pbf кеш Overpass не используется, а overpass_date игнорируется: снимком служит сам файл, и зоны остановок метро читаются всегда. snapshot_time(path) возвращает момент, на который составлен файл, из его заголовка (osmosis_replication_timestamp, задаётся в выгрузках Geofabrik).

Загрузка территории из Geofabrik¶

download_osm_pbf заменяет загрузку из Overpass выгрузками Geofabrik. Территория задаётся так же, как в функциях построения графов: функция выбирает наименьшую выгрузку, покрывающую территорию, скачивает её один раз (докачивая прерванную загрузку и сверяя md5, который публикует Geofabrik), вырезает территорию с помощью split_by_polygons и возвращает небольшой файл. use_pbf принимает те же аргументы вместо пути, скачивает файл и читает из него внутри блока:

import iduedu

with iduedu.use_pbf(osm_id=1114252, region="northwestern-fed-district"):
    boundary = iduedu.get_4326_boundary(osm_id=1114252)
    graph = iduedu.get_intermodal_graph(territory=boundary, clip_by_territory=True)

with iduedu.use_pbf(territory=city_polygon):        # the extract is chosen from the territory
    walk = iduedu.get_walk_graph(territory=city_polygon)

path = iduedu.download_osm_pbf(osm_id=1114252, region="northwestern-fed-district")  # or just the file

С region граница osm_id читается из выгрузки, и запрос к Overpass не выполняется; без него граница один раз загружается через Overpass, чтобы выбрать выгрузку. Для territory= (полигон или GeoDataFrame) не нужно ни то, ни другое. Выгрузки и вырезанные файлы кешируются в config.overpass_cache_dir (geofabrik/ и geofabrik/territories/); уже существующий вырезанный файл возвращается без загрузки, а закешированная выгрузка используется повторно, пока update=True не запросит более новый файл Geofabrik. geofabrik_regions() перечисляет выгрузки с их контурами, find_geofabrik_region(territory) называет наименьшую покрывающую.

Файлы городов из региональной выгрузки¶

Запрос к файлу размером со страну каждый раз просматривает его целиком. Нарежьте его на небольшие файлы городов один раз, за один проход для всех городов региона:

from iduedu import snapshot_time, split_by_polygons

paths = split_by_polygons(
    "russia-northwestern-fed-district-latest.osm.pbf",
    {"spb": spb_polygon, "petrozavodsk": ptz_polygon},
    "cities/",
    location_storage="dense_file_array",     # disk-backed node index for large extracts
)
snapshot_time(paths["spb"])                  # the extract's replication timestamp is kept

Каждый файл города хранит целиком и с тегами: улицы (highway, railway, public_transport), касающиеся полигона; касающиеся его отношения-маршруты общественного транспорта со всеми участниками, в том числе за пределами полигона; для метро — все отношения, имеющие общий узел с линией (её зоны остановок), их участников и содержащие их группы зон остановок; а также отношения, перечисленные в keep_relations (например, границу, чтобы osm_id= продолжал работать). Графы, построенные по файлу города, получаются такими же, как по региональному файлу, для того же полигона или любого полигона внутри него.

Отличия от Overpass¶

  • Элементы возвращаются в порядке идентификаторов. Overpass возвращает ответы с маршрутами в порядке квадтайлов (qt), поэтому узлы и рёбра графа общественного транспорта могут быть пронумерованы иначе, хотя граф тот же.

  • Точки на границе полигона считаются внутренними. В редких случаях Overpass может иначе обрабатывать точные попадания на границу и очень длинные стороны полигона.

  • Поддерживаются только фильтры по тегам (["k"], [!"k"], ["k"="v"], ["k"!="v"], ["k"~"re"], ["k"!~"re"], с необязательным флагом ,i для регулярных выражений); другой синтаксис Overpass в custom_filter вызывает UnsupportedFilterError. Регулярные выражения обрабатываются модулем Python re.

  • Данные, которых нет в файле, найти нельзя: у участников отношения, отсутствующих в файле, нет геометрии. Используйте split_by_polygons (или полную региональную выгрузку), а не узкую обрезку.

  • split_by_polygons отбирает улицы пространственно, только если у них есть один из ключей way_keys; для custom_filter по другим ключам при нарезке файлов городов нужен way_keys=None (или список, включающий эти ключи).

Индикаторы прогресса и журналирование¶

from iduedu import config

config.set_enable_tqdm(False)  # hide progress bars while public-transport routes are parsed
config.configure_logging(level="INFO")
config.configure_logging(level="DEBUG", to_file="iduedu.log")

IduEdu ведёт журнал через loguru, он доступен как config.logger. Уровень по умолчанию — WARNING. configure_logging заменяет все приёмники общего логгера loguru, включая добавленные вашим приложением, затем пишет в стандартный поток ошибок и, с to_file, в файл, который ротируется по достижении 20 МБ и хранится 14 дней. json=True пишет только сообщение без времени и уровня — для сборщиков, которые добавляют их сами.

set_overpass_date(date=None, *, year=None, month=None, day=None)[исходный код]¶

Задаёт дату снимка для запросов к Overpass.

Дата хранится в формате ISO 8601 UTC: YYYY-MM-DDTHH:MM:SSZ и подставляется в заголовок запроса Overpass как [date:"..."]. Этот метод позволяет зафиксировать данные OSM на определённом историческом снимке или вернуться к «текущим» данным.

Примеры использования:

  • set_overpass_date() или set_overpass_date(None) — сбросить дату (без [date:...] в запросах).

  • set_overpass_date(date="2020-01-01") -> 2020-01-01T00:00:00Z.

  • set_overpass_date(date="2020-01-01T12:34:56Z") -> сохраняет нормализованное значение этой метки времени.

  • set_overpass_date(year=2020) -> 2020-01-01T00:00:00Z.

  • set_overpass_date(year=2020, month=5) -> 2020-05-01T00:00:00Z.

  • set_overpass_date(year=2020, month=5, day=10) -> 2020-05-10T00:00:00Z.

Параметры:

  • date (str | None) – Строка даты в формате YYYY-MM-DD или YYYY-MM-DDTHH:MM:SSZ. Если она передана, year, month и day должны быть None.

  • year (int | None) – Год. Если дата задаётся без date, нужно указать хотя бы год; month и day необязательны и по умолчанию дают 1 января.

  • month (int | None) – Месяц (1–12). Необязателен вместе с year. По умолчанию 1 (январь).

  • day (int | None) – День (1–31). Необязателен вместе с year и month. По умолчанию 1.

Исключение:

ValueError – Если переданы и date, и любой из year, month, day, если строка даты в неподдерживаемом формате или если получившаяся дата недопустима.

set_osm_source(source, *, path=None)[исходный код]¶

Выбирает источник данных OpenStreetMap.

"overpass" (по умолчанию) отправляет запросы в Overpass API. "pbf" отвечает на те же запросы по локальному файлу OSM (.osm.pbf, .osm, .opl) через необязательную зависимость pyosmium (pip install 'iduedu[pbf]'); кеш Overpass и overpass_date тогда не используются.

Параметры:

  • source (Literal['overpass', 'pbf']) – "overpass" или "pbf".

  • path (str | PathLike | None) – Файл OSM для "pbf". Можно не указывать, если pbf_path уже задан. Для "overpass" только сохраняется.

Исключение:

  • ValueError – Для неизвестного источника или "pbf" без файла.

  • FileNotFoundError – Если файл не существует.

  • ImportError – Если выбран "pbf", а pyosmium не установлен.

use_pbf(path=None, *, osm_id=None, territory=None, region=None, **download_kwargs)[исходный код]¶

Временно читает данные OSM из локального файла; при выходе восстанавливается прежний источник.

Файл либо задаётся путём path, либо скачивается для территории: osm_id, territory, region и любые другие именованные аргументы без изменений передаются в download_osm_pbf(), которая выбирает выгрузку Geofabrik, кеширует её и вырезает территорию. Уже закешированный файл используется повторно без загрузки. Также доступна как iduedu.use_pbf.

Параметры:

  • path (str | PathLike | None) – Файл OSM (.osm.pbf, .osm, .opl).

  • osm_id (int | None) – Идентификатор отношения OSM территории для загрузки, вместо path.

  • territory (Polygon | MultiPolygon | GeoDataFrame | GeoSeries | None) – Полигон территории в EPSG:4326 либо GeoDataFrame/GeoSeries, вместо path.

  • region (str | None) – Идентификатор региона Geofabrik, из которого вырезается территория; если не указан, выбирается автоматически.

  • **download_kwargs – Прочие аргументы download_osm_pbf() (update, out_dir, name, …).

Исключение:

ValueError – Если переданы и path, и аргументы загрузки, или ни то, ни другое.

Тип результата:

Iterator[Config]

Пример

>>> with config.use_pbf("berlin.osm.pbf"):
...     walk = get_walk_graph(territory=polygon)
>>> with iduedu.use_pbf(osm_id=1114252, region="northwestern-fed-district"):

build_overpass_header(*, timeout=None, date=None)[исходный код]¶

Формирует заголовок запроса Overpass для ответов в JSON.

Параметры:

  • timeout (int | None) – Необязательный тайм-аут в секундах вместо настроенного. Если не указан, используется тайм-аут по умолчанию.

  • date (str | None) – Необязательная дата снимка Overpass в формате ISO UTC вместо настроенной. Если не указана, используется self.overpass_date.

Тип результата:

str

Результат:

Строка заголовка, например [out:json][timeout:120]; или [out:json][timeout:120][date:"2020-01-01T00:00:00Z"];.

Исключение:

ValueError – Если итоговый тайм-аут не положителен.

set_rate_limit(*, min_interval=None, max_retries=None, backoff_base=None)[исходный код]¶

Настраивает темп запросов к Overpass и повторные попытки.

Параметры:

  • min_interval (float | None) – Минимальная пауза между запросами к Overpass в секундах.
