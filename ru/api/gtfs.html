Общественный транспорт из GTFS¶

IduEdu может построить статический iduedu.UrbanGraph общественного транспорта по локальному фиду GTFS Schedule. Источником может быть папка с таблицами *.txt, ZIP-архив, уже прочитанный iduedu.gtfs.GTFSFeed или список таких источников, объединённых в один фид (см. Объединение нескольких фидов). Ноутбук Общественный транспорт из GTFS проходит все описанные ниже шаги на небольших синтетических фидах.

Построение графа¶

from iduedu import get_gtfs_public_transport_graph

public_transport = get_gtfs_public_transport_graph(
    "feed.zip",
    service_date="2026-08-04",
    start_time="07:00:00",
    end_time="10:00:00",
)

service_date применяет calendar.txt и calendar_dates.txt. Принимает date или datetime Python, YYYY-MM-DD или YYYYMMDD. start_time включается в окно, end_time — нет; оба принимают строки времени GTFS, значения time Python или секунды. Если время окончания раньше времени начала, выбирается ночное окно через полночь.

Без service_date граф содержит все варианты маршрутов, которые ходят хотя бы в один день, а время ожидания — время среднего дня: каждый отдельный день обслуживания рассчитывается по своим рейсам, и ожидание усредняется с одинаковым весом каждого календарного дня по дням, в которые ходит вариант маршрута. Дни берутся из собственного календаря фида (не более 366 дней от его начала) или из service_period=(first, last), например одной эталонной недели. Интервал всегда считается только между отправлениями одного дня: до октября 2026 года рейсы всех дней ставились на одни часы, и отправление буднего дня в 08:00 рядом с субботним в 08:10 давало 10-минутный «интервал», которого не видел ни один пассажир, — ожидание получалось примерно вдвое меньше, чем в любой реальный день. start_time/end_time действуют внутри каждого дня, например start_time="06:00", end_time="22:00" для дневного движения.

# the average day of one reference week, daytime service only
average_week = get_gtfs_public_transport_graph(
    "feed.zip",
    service_period=("2026-10-12", "2026-10-18"),
    start_time="06:00",
    end_time="22:00",
)

service_dates=[...] вместо этого явно перечисляет дни, например эталонную неделю плюс собственные недели объединённых источников, которые в ту неделю не действовали. Каждый день по-прежнему содержит только свои рейсы, поэтому дни разных лет не смешиваются. service_date, service_period и service_dates нельзя сочетать. Фид без calendar.txt/calendar_dates.txt считается одним днём.

Обязательные и необязательные таблицы¶

Для построения нужны agency.txt, stops.txt, routes.txt, trips.txt и stop_times.txt. Также должна быть хотя бы одна из таблиц calendar.txt и calendar_dates.txt.

Если они есть, читаются также frequencies.txt, shapes.txt, pathways.txt, levels.txt и feed_info.txt. transfers.txt и точная маршрутизация пересадок с учётом времени пока не реализованы.

Базовые типы маршрутов представлены как tram (0), subway (1), train (2), bus (3), ferry (4), cable_tram (5), aerial_lift (6), funicular (7), trolleybus (11) и monorail (12). Расширенные типы маршрутов Google сопоставляются по явным диапазонам: 100–117 train, 200–209 coach (отдельно от городских автобусов), 400–404 и 406–499 subway, 405 monorail, 700–716 bus, 800–899 trolleybus, 900–906 tram, 1000 и 1200 ferry, 1300 aerial_lift, 1400 funicular и 1500 taxi. Любой другой код, включая прочие диапазоны 300, 500, 600, 1600 и 1700, остаётся public_transport, а не угадывается по соседним кодам.

Статическая модель времени¶

Рейсы с одинаковыми маршрутом, направлением, формой, порядком остановок и правилами посадки и высадки образуют вариант маршрута. Для каждого перегона варианта time_min — медиана времени по расписанию от отправления с одной остановки до прибытия на следующую.

Рёбра посадки описывают ожидаемое ожидание, а не движение транспорта:

  • для движения по расписанию берётся половина среднего интервала между соседними отправлениями линии с остановки в один и тот же день, усреднённая по дням, как описано выше. Линия — это маршрут, уходящий с остановки к одной и той же следующей остановке: учитываются все её варианты — ветви на общем участке, укороченные рейсы, экспрессы, — поэтому ожидание соответствует линии, которую ждёт пассажир, а не одному её варианту. Направление определяет следующая остановка, а не direction_id;

  • для движения по frequencies.txt берётся headway_secs / 120, с усреднением по длительности, если периоды частот пересекаются с выбранным окном;

  • у остановки варианта маршрута с единственным отправлением по расписанию интервал оценить нельзя, поэтому её ребро посадки по умолчанию не создаётся. Задайте single_departure_wait_min, чтобы сохранить его с явным значением по умолчанию.

Рёбра посадки и высадки всегда имеют length_meter = 0. У высадки также time_min = 0. Время ожидания в GTFS берётся из фида и не использует значения по умолчанию из iduedu.TransportRegistry.

Геометрия и расстояние¶

Если shapes.txt даёт пригодную геометрию маршрута, геометрия перегона вырезается из соответствующей формы, а length_meter — её измеренная длина. Иначе строится прямая между соседними точками остановок маршрута, а оценкой пройденного расстояния считается sqrt(2) * straight_line_length. Поправка на корень из двух применяется только к рёбрам движения транспорта, таким как bus, tram или subway, и никогда — к посадке или высадке.

Система координат графа должна быть проецированной, в метрах. Если crs не задан, IduEdu подбирает локальную систему UTM по остановкам фида.

Объединение нескольких фидов¶

Город часто публикуется несколькими фидами, и каждый фид нумерует свои маршруты, рейсы и остановки по-своему. Передайте список источников, чтобы объединить их перед построением графа:

public_transport = get_gtfs_public_transport_graph(
    ["subway.zip", "bus.zip"],
    service_date="2026-08-04",
    start_time="07:00:00",
    end_time="10:00:00",
)

Список объединяется функцией iduedu.merge_gtfs_feeds(), которая дополняет каждый идентификатор источником, поэтому маршрут 1 одного фида и маршрут 1 другого остаются разными. Вызовите её напрямую, чтобы выбрать префиксы или слить остановки, которые разные перевозчики публикуют для одного места:

from iduedu import get_gtfs_public_transport_graph, merge_gtfs_feeds

feed = merge_gtfs_feeds(["subway.zip", "bus.zip"], merge_stops_within=20)
public_transport = get_gtfs_public_transport_graph(feed, service_date="2026-08-04")

По умолчанию остановки остаются раздельными: слияние меняет топологию сети, а выведенная пересадка выглядела бы как опубликованная. Для фидов разных перевозчиков подходят расстояния около 15–25 м.

Фиды из нескольких каталогов часто пересекаются: две версии одного фида, национальный и городской фиды одного оператора, зеркало и оригинал. deduplicate=True учитывает такое движение один раз. Платформы разных источников ближе duplicate_platform_tolerance (по умолчанию 0,5 м — та же координата, опубликованная повторно, тогда как разные платформы одного фида бывают и в 1–3 м друг от друга) становятся одной платформой, а рейс, который другой источник уже проводит через те же платформы в то же время, отбрасывается. Платформы одного фида никогда не сливаются друг с другом, как и станции, входы и зоны посадки:

feed = merge_gtfs_feeds(["city.zip", "national.zip"], deduplicate=True)

iduedu.deduplicate_across_feeds() применяет те же правила к таблицам, объединённым другим способом, и возвращает, сколько платформ и рейсов удалено.

Станции, переходы и объединение с пешеходной сетью¶

pathways.txt создаёт внутристанционные рёбра pathway. Явное traversal_time переводится из секунд в минуты; иначе время оценивается по длине перехода и walk_speed_m_per_min. Входы, узлы, зоны посадки и платформы станций сохраняются, если на них ссылаются обслуживаемые остановки или переходы.

Остановка, у которой указан parent_station, связывается с ним двунаправленным ребром station_link нулевой стоимости. Связываются только остановки, уже вошедшие в граф. Без этих рёбер станция, описанная вплоть до зон посадки, оставила бы свои платформы в отдельной компоненте, которую удаляет keep_largest_subgraph.

Чтобы присоединить общественный транспорт GTFS к пешеходному графу OSM, сначала постройте пешеходный слой и используйте ту же систему координат:

from iduedu import get_gtfs_public_transport_graph, get_walk_graph, join_pt_walk_graph

walk = get_walk_graph(osm_id=1114252)
public_transport = get_gtfs_public_transport_graph(
    "feed.zip",
    service_date="2026-08-04",
    start_time="07:00:00",
    end_time="10:00:00",
    crs=walk.crs,
)
intermodal = join_pt_walk_graph(public_transport, walk)

Справочник API¶

iduedu.get_gtfs_public_transport_graph(feed, *, service_date=None, service_period=None, service_dates=None, start_time=None, end_time=None, crs=None, single_departure_wait_min=None, walk_speed_m_per_min=83.33333333333333)[исходный код]

Строит статический UrbanGraph общественного транспорта по локальному фиду GTFS.

Веса посадки рассчитываются эвристикой половины интервала первой итерации. Для движения по расписанию берётся половина среднего интервала между соседними отправлениями одного варианта маршрута с одной остановки. Для frequencies.txt — headway_secs / 120.

Интервал — это промежуток между отправлениями одного дня. С service_date граф описывает расписание этого дня. Без него каждая остановка варианта маршрута получает ожидание среднего дня: ожидание каждого дня обслуживания из service_period — или из собственного календаря фида, не более 366 дней от его начала, — рассчитанное только по рейсам этого дня и затем усреднённое с одинаковым весом каждого календарного дня по дням, в которые эта остановка обслуживается. Рейсы, не выполняемые ни в один из этих дней, не учитываются. Фид без calendar/calendar_dates считается одним днём.

start_time/end_time ограничивают отправления внутри каждого дня; None означает отсутствие ограничения.

Параметры:

  • feed (Union[str, Path, GTFSFeed, Sequence[str | Path | GTFSFeed]]) – Папка с текстовыми файлами GTFS, ZIP-архив GTFS, уже прочитанный iduedu.gtfs.GTFSFeed или последовательность любых из них. Последовательность сначала объединяется функцией iduedu.merge_gtfs_feeds(), которая дополняет идентификаторы источником; передайте объединённый фид сами, если нужно управлять префиксами или сливать остановки разных фидов.

  • service_date (date | datetime | str | None) – Необязательная дата обслуживания, используется с calendar.txt и calendar_dates.txt. Принимает date, YYYY-MM-DD или YYYYMMDD.

  • service_period (tuple[date | datetime | str, date | datetime | str] | None) – Необязательные даты (first, last), обе включительно, по которым усредняется ожидание вместо собственного календаря фида (например, эталонная неделя). Нельзя сочетать с service_date.

  • service_dates (Optional[Sequence[date | datetime | str]]) – Необязательный явный список дней для усреднения ожидания, например эталонная неделя плюс собственные недели объединённых источников, не действовавших в ту неделю. Каждый день по-прежнему содержит только свои рейсы, поэтому дни разных лет не смешиваются. Нельзя сочетать с service_date или service_period.

  • start_time (time | str | int | float | None) – Нижняя граница времени отправления, включительно. None — без ограничения.

  • end_time (time | str | int | float | None) – Верхняя граница времени отправления, не включительно. None — без ограничения.

  • crs (Any | None) – Проецированная целевая система координат. Если не задана, подбирается локальная система UTM.

  • single_departure_wait_min (float | None) – Явное значение ожидания для остановки варианта маршрута с одним отправлением по расписанию. Если None, её ребро посадки не создаётся.

  • walk_speed_m_per_min (float) – Скорость по умолчанию для переходов без явного времени прохождения.

Тип результата:

UrbanGraph

iduedu.merge_gtfs_feeds(sources, *, prefixes=None, merge_stops_within=None, deduplicate=False, duplicate_platform_tolerance=0.5, crs=None, validate=True)[исходный код]¶

Объединяет несколько фидов GTFS в один, пригодный для функции построения графа.

Идентификаторы дополняются источником, поэтому route_id 1 в двух фидах становится двумя разными маршрутами. Определения и ссылки переписываются вместе, а пустые необязательные ссылки остаются пустыми.

Параметры:

  • sources (Sequence[str | Path | GTFSFeed]) – Пути к папкам или ZIP-архивам GTFS либо уже прочитанные фиды. Единственный источник возвращается без изменений, если не запрошено слияние остановок, поэтому там, где объединение не нужно, функция ничего не делает.

  • prefixes (Optional[Sequence[str]]) – По одному префиксу на источник. По умолчанию — имя файла каждого источника, с числовым суффиксом, если у двух источников оно совпадает.

  • merge_stops_within (float | None) – Расстояние в метрах, ближе которого остановки разных фидов считаются одним местом и сливаются в один узел. None (по умолчанию) оставляет все остановки раздельными: слияние меняет топологию сети, а молчаливое слияние сделало бы выведенную пересадку неотличимой от опубликованной. Для фидов разных перевозчиков подходят значения около 15–25 м; 1 м, используемый для платформ OSM, здесь слишком мал, потому что два перевозчика снимают один и тот же бордюр независимо.

  • deduplicate (bool) – Учесть один раз то, что несколько источников публикуют дважды: слить платформы разных источников в пределах duplicate_platform_tolerance метров и отбросить рейсы, которые другой источник уже выполняет так же. См. deduplicate_across_feeds(). По умолчанию выключено: это изменяет фид.

  • duplicate_platform_tolerance (float) – Расстояние в метрах, в пределах которого платформы двух источников считаются одной, когда включён deduplicate.

  • crs (Any | None) – Проецированная система координат в метрах для проверки расстояний. Если не задана, подбирается по остановкам.

  • validate (bool) – Запустить iduedu.gtfs.validate_gtfs_feed() на результате. Не отключайте: именно это делает объединение проверяемым, а не просто правдоподобным.

Тип результата:

GTFSFeed

Результат:

iduedu.gtfs.GTFSFeed, у которого source перечисляет объединённые источники.

Исключение:

  • ValueError – Если источники не переданы или число префиксов не совпадает с числом источников.

  • GTFSValidationError – Если объединённый фид нарушает требования GTFS.

iduedu.deduplicate_across_feeds(tables, prefixes, *, platform_tolerance=0.5, crs=None)[исходный код]¶

Учитывает один раз то, что несколько объединённых фидов публикуют дважды. Изменяет tables на месте.

Каталоги пересекаются: две версии одного фида, национальный и городской фиды одного оператора, зеркало и оригинал. При объединении с дополненными идентификаторами копии никогда не конфликтуют — они лежат рядом, и граф получает два варианта маршрута там, где в городе ходит один. Их удаляют два правила, оба намеренно узкие, потому что ошибочное слияние хуже оставшегося дубликата:

  • Платформы — строки stops с location_type 0 или пустым, где пассажиры садятся; функция построения графа делает из них узлы platform, а место остановки транспорта — отдельный узел для каждого варианта маршрута, и его это правило не затрагивает. Платформы разных источников в пределах platform_tolerance метров считаются одной платформой. Значение по умолчанию 0,5 м получено измерением: из 125 703 платформ городов, объединённых из нескольких фидов, у 63 % в пределах 0,5 м была платформа другого источника (та же координата, опубликованная повторно), тогда как разные платформы одного фида бывают и в 1–3 м друг от друга. Станции, входы, общие узлы и зоны посадки никогда не сливаются, как и платформы одного источника.

  • Рейсы — после этого рейс одного источника считается копией рейса другого, если оба имеют одинаковый route_type, проходят через те же платформы с теми же временами прибытия и отправления (в секундах), правилами посадки и высадки и, для рейсов по частотам, теми же интервалами. Его сохраняет источник, идущий первым при сортировке.

Параметры:

  • tables (dict[str, DataFrame]) – Объединённые таблицы с ключами по имени таблицы GTFS без .txt, идентификаторы в виде <prefix>:<id>.

  • prefixes (Sequence[str]) – Префикс каждого источника.

  • platform_tolerance (float) – Расстояние в метрах, в пределах которого платформы двух источников считаются одной.

  • crs (Any | None) – Проецированная система координат в метрах для проверки расстояний; если не задана, подбирается автоматически.

Тип результата:

dict[str, int]

Результат:

{"platforms_fused": n, "trips_dropped": m}.
