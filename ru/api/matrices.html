Матрицы¶

Кратчайшие пути¶

Функции кратчайших путей IduEdu работают с объектами UrbanGraph и по возможности повторно используют закешированную матрицу смежности графа. Расстояния измеряются в единицах выбранного веса рёбер:

time_min

Время в пути в минутах.

length_meter

Сетевое расстояние в метрах.

Работающие примеры для всех перечисленных ниже функций — в Кратчайшие пути и OD-матрицы.

Выбор функции¶

Используйте single_source_dijkstra() для одного источника, multi_source_dijkstra() для ближайшего из множества источников или dijkstra_parallel() для отдельной строки на каждый источник. Каждая принимает output="distances", "paths" или "both".

Используйте od_matrix() для заданных множеств точек отправления и назначения, с mode="all_to_all" или "pairwise". Используйте iter_od_matrix(), чтобы обрабатывать блоки строк по точкам отправления. single_source_dijkstra_path() возвращает один маршрут в виде списка. Прежние функции *_path_length и multi_source_dijkstra_path объявлены устаревшими (см. Устаревшие функции).

Используйте path_to_edges(), чтобы превратить маршрут по узлам в упорядоченный GeoDataFrame реальных рёбер графа. Так сохраняются изогнутая геометрия рёбер и атрибуты транспорта для отображения на карте.

Расстояния и пути за один поиск¶

single_source_dijkstra(), multi_source_dijkstra(), dijkstra_parallel() и od_matrix() принимают output:

  • "distances" возвращает разреженные числовые результаты.

  • "paths" возвращает разреженные результаты с упорядоченными списками идентификаторов узлов.

  • "both" возвращает ShortestPathResult с согласованными таблицами distances и paths, рассчитанными одними и теми же поисками.

Для совместимости od_matrix по умолчанию использует output="distances". Три общие функции Дейкстры по умолчанию используют output="both".

result = graph.od_matrix(
    origins_nodes=origins,
    destination_nodes=destinations,
    weight="time_min",
    cutoff=30,
    output="both",
)
distances = result.distances
paths = result.paths
route = result.get_path(origins[0], destinations[0])

Обе матрицы сохраняют порядок и метки входных данных. Отсутствующие маршруты и маршруты за порогом имеют расстояние np.inf и путь None (pandas может показывать отсутствующий разреженный путь как NaN). Маршрут из узла в него же имеет нулевую стоимость и путь [node]; рёбра нулевой стоимости сохраняются. Порог включается в диапазон и задаётся в единицах выбранного веса. threshold остаётся псевдонимом в функциях OD; указание обоих имён вызывает ValueError. dtype задаёт тип хранения возвращаемых расстояний; арифметика ядра остаётся float32, даже если запрошен выходной тип float64.

Поиск от одного источника, от ближайшего источника и независимые поиски¶

# One source, with only the requested targets in the result.
single = graph.single_source_dijkstra(
    source, target_nodes=destinations, cutoff=30,
)
route = single.get_path(destinations[0])

# One combined source set: choose the closest source for each target.
nearest = graph.multi_source_dijkstra(source_nodes=origins, cutoff=30)
winning_sources = nearest.nearest_sources

# Independent result row for every source object or node.
independent = graph.dijkstra_parallel(
    source_nodes=origins, target_nodes=destinations,
    cutoff=30, output="both", max_workers=4,
)

Для поиска от одного источника и от ближайшего источника target_nodes=None возвращает только достижимые узлы в порядке узлов графа. Явно заданные цели сохраняют входной порядок и включают недостижимые. Независимые поиски без явных целей используют объединение достижимых узлов как столбцы. При равенстве расстояний до нескольких источников выбирается источник, идущий первым в порядке узлов графа; nearest_sources содержит идентификаторы узлов графа, а не метки объектов-источников.

reverse=True ищет по транспонированному ориентированному графу. Возвращаемые пути идут в направлении исходного графа, к источнику. Для неориентированных графов этот параметр ни на что не влияет. Результаты OD всегда идут в направлении от отправления к назначению, в том числе когда реализация ищет со стороны меньшего множества назначений.

Попарные запросы OD¶

pairs = graph.od_matrix(
    origins_nodes=origins,
    destination_nodes=destinations,
    mode="pairwise",
    output="both",
)

Попарные входные данные должны иметь одинаковую длину. Каждая точка отправления сопоставляется с точкой назначения на той же позиции. Результаты имеют MultiIndex (origin, destination) и один столбец: dist для стоимостей или path для маршрутов. Так не строятся все комбинации отправлений и назначений.

Ленивое хранение маршрутов¶

result = graph.od_matrix(
    origins_nodes=origins,
    destination_nodes=destinations,
    cutoff=30,
    output="both",
    path_storage="lazy",
)
distances = result.distances        # Already calculated.
route = result.get_path(origins[0], destinations[0])
assert not result.paths_materialized
paths = result.paths                # Materialize and cache the whole table.
assert result.paths_materialized

Ленивое хранение требует output="both". Оно сохраняет компактные деревья предшественников для обработанных узлов, а не создаёт сразу все списки маршрутов. get_path восстанавливает один маршрут без повторного поиска Дейкстры. Сопоставление идентификаторов узлов и предшественники — снимки: последующие правки графа не меняют сохранённые пути. Геометрии не сохраняются; path_to_edges на изменённом графе использует текущие рёбра этого графа.

Если переданы таблицы объектов, используйте в get_path метки объектов. Повторяющиеся входные узлы поддерживаются, но неоднозначные повторяющиеся метки требуют доступа по позиции: result.get_path_at(row, column). Для результатов в виде Series используйте get_path(target) или get_path_at(row). Неизвестные метки вызывают KeyError; для известных недостижимых пар возвращается None.

Ленивые деревья всё равно занимают память пропорционально числу обработанных узлов на каждый уникальный поиск. Они могут оказаться больше, чем несколько сразу построенных маршрутов, поэтому ленивое хранение полезнее всего, когда многие маршруты имеют общие участки дерева, а просматриваться будут лишь некоторые из них.

Большие расчёты и рабочая память¶

batch_size в od_matrix и dijkstra_parallel ограничивает число одновременно выполняемых поисков от уникальных источников. Полный результат и все сохранённые ленивые деревья по-прежнему остаются в памяти. Используйте iter_od_matrix(), чтобы обрабатывать блоки строк по точкам отправления:

for block in graph.iter_od_matrix(
    origins_nodes=origins,
    destination_nodes=destinations,
    cutoff=30,
    output="both",
    path_storage="lazy",
    batch_size=256,
):
    process_distances(block.distances)
    # Inspect selected routes with block.get_path(...), then release block.

В попарном режиме строки назначений нарезаются вместе с их отправлениями. Сопоставление объектов с узлами выполняется один раз. Сохранение всех выданных блоков сохраняет и их память; не меняйте граф, пока перебираете итератор.

Таблицы расстояний строятся без плотной промежуточной матрицы размером OD. Поиски общие для объектов, сопоставленных с одним узлом графа, останавливаются, когда обработаны все запрошенные цели, и по возможности идут со стороны меньшего множества уникальных точек OD. max_workers временно задаёт число потоков Numba; прежнее значение восстанавливается, в том числе при ошибке поиска.

Офлайн-бенчмарк на синтетических данных запускается командой python -m benchmarks.bench_routing. Он сравнивает раздельные вызовы с совместными расчётами при немедленном и ленивом хранении после прогрева JIT. Измерения выделения памяти используют tracemalloc и не учитывают собственный аллокатор Numba; это не измерения пикового RSS процесса. Соотношения времени зависят от структуры графа и запрошенных путей.

Таблицы хранят сопоставления узлов как Series в attrs. Перед объединением блоков средствами pandas очистите их метаданные, относящиеся к блоку, потому что pandas сравнивает attrs обычным равенством:

tables = []
for table in graph.iter_od_matrix(
    origins_nodes=origins, destination_nodes=destinations,
):
    table.attrs = {}
    tables.append(table)
combined = pd.concat(tables)

Входные GeoDataFrame¶

Некоторые функции принимают GeoDataFrame через gdf_sources, gdf_origins или gdf_destinations. Если в таблице уже есть graph_node_id (или столбец, заданный через graph_node_column), это сопоставление используется напрямую. Иначе объекты сопоставляются с ближайшими узлами графа. Проецирование объектов на рёбра перед расчётом OD описано в Объекты, ближайшие узлы и проецирование на граф.

single_source_dijkstra

Поиск от одного узла; возвращает расстояния, пути или и то и другое за один обход.

multi_source_dijkstra

Поиск от ближайшего элемента одного общего множества источников.

multi_source_dijkstra_nearest_source

Возвращает столбцы ближайшего source_node и dist для каждого достижимого узла.

dijkstra_parallel

Выполняет независимые поиски, объединяя работу для источников, сопоставленных с одним узлом.

od_matrix

Рассчитывает расстояния OD, маршруты по узлам или и то и другое — по одному поиску на уникальный источник.

iter_od_matrix

Выдаёт результаты OD блоками строк по точкам отправления, с теми же параметрами, что od_matrix.

ShortestPathResult

Расстояния и пути из одних и тех же поисков Дейкстры.

single_source_dijkstra_path

Возвращает один кратчайший маршрут по узлам или [], если цель недостижима или за порогом.

path_to_edges

Преобразует упорядоченный путь по узлам в упорядоченные рёбра графа.

Устаревшие функции¶

Эти обёртки выдают DeprecationWarning начиная с 2.4.1 и будут удалены в IduEdu 3.0. Каждая вызывает одну общую функцию с фиксированным output:

  • single_source_dijkstra_path_length → single_source_dijkstra(..., output="distances")

  • multi_source_dijkstra_path_length → multi_source_dijkstra(..., output="distances")

  • dijkstra_path_length_parallel → dijkstra_parallel(..., output="distances")

  • multi_source_dijkstra_path → od_matrix(..., output="paths"). Несмотря на название, она рассчитывает независимые маршруты от отправлений к назначениям, а не поиск от ближайшего источника.

single_source_dijkstra_path_length

Возвращает разреженную Series расстояний с индексом по достижимым узлам графа.

multi_source_dijkstra_path_length

Возвращает расстояния до ближайшего источника; входные данные как у multi_source_dijkstra.

dijkstra_path_length_parallel

Возвращает независимые строки расстояний; входные данные как у dijkstra_parallel.

multi_source_dijkstra_path

Обёртка совместимости для od_matrix(output='paths'), включая попарный режим.
